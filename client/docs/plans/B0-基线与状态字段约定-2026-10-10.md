## 3. B2 约定：自动目标快照与稳定标识

### 3.1 目标配置（Dart 侧唯一权威）

新增 `lib/services/automation/automation_settings_store.dart`，SharedPreferences 单 key `auto_book_settings_v1`（JSON 字符串，**带版本**）。结构：

```json
{
  "schemaVersion": 1,
  "configVersion": 7,
  "target": {
    "scope": "user:<本地用户作用域标识>",
    "kind": "syncId" | "localId",
    "value": "3f2a…",
    "accountId": 12,
    "confirmedAt": "2026-10-10T12:00:00Z",
    "migratedFrom": "legacy_current_ledger"
  },
  "notifyMode": "confirm_and_fault",
  "setupProgress": {"aiChecked": true, "targetChosen": true, "sources": ["notify"], "verifiedAt": null}
}
```

- `schemaVersion`：结构不兼容时才递增；读取到更高版本时**只读不写**并显示「待生效」，不降级覆盖。
- `configVersion`：单调递增整数。每次 target/notifyMode 变更 +1，写盘成功后**再**刷新原生缓存（`AutoBookTargetStore`）。捕获侧只认「缓存中的 configVersion ≤ 已知最大值」的有效快照。
- 旧 key 只读导入：`current_ledger_id` 等旧设置**不删除、不改写**。

### 3.2 稳定标识口径（含 syncId 为空）

| 情形 | kind | value | 说明 |
|---|---|---|---|
| 账本有非空 syncId | `syncId` | syncId 原值 | 首选；跨设备稳定 |
| 账本 syncId 为空（历史本地账本） | `localId` | `"<本地 int id>"` | **仅在用户作用域内有效**；scope 必填，防止跨账号误命中 |
| 共享账本 | 同上 | 同上 | 共享账本用其**在本机的账本行**标识；不把共享账本的临时映射 ID（synthetic 负数 id / 镜像表 id）写入 target.value |

- 解析顺序：`kind=syncId` → 按 syncId 找账本行；找不到则**判定目标失效**（不回落本地 id）。`kind=localId` → 按本地 id 找账本行；该行后续补写 syncId **不影响**命中（本地 id 恒定），此时**不自动改写**已有 target（避免配置在用户未确认时变动）；仅在用户下次打开目标设置页时提示可升级为 syncId。
- 事件快照迁移：已冻结的事件保留**捕获时刻**的 targetRef 原值，不因账本后续补写 syncId 而重写；解析仍按上表规则，localId 在本机永远可解析。
- scope 口径：本地无账号概念时用 `'local'`；已登录 SmartBook Cloud 时用 `'user:<userId>'`（取自登录态；无稳定 userId 时退回 `'local'` 并在 UI 标注「仅本机」）。**切账号后 target 判定为不匹配 → 停止自动写入并要求重新确认**，绝不沿用上一账号的目标。

### 3.3 冻结与传递

1. **捕获时冻结**：原生入队时读取已缓存的目标快照 `{targetRef, configVersion}`，随封套写入；缓存缺失/版本未知 → 封套标记 `targetState = "undetermined"`（目标待确定），**不回退到当时浏览的账本**。
2. **事件持久化**：`auto_book_events` 增加可空字段 `targetRef`（TEXT）、`targetConfigVersion`（INT NULL）、`targetState`（TEXT 默认 `'resolved'`，取值 `resolved` / `undetermined` / `invalid`）。解析成功时回填 `ledgerId`（本地 int），失败则 `ledgerId` 保持 NULL 且 `targetState=invalid`。
3. **候选确认与失败重放**：确认入账、retryDraft、`_replayInput` 一律使用**事件行上的快照**，不再现算目标。
4. **冷启动未就绪**：`targetState=undetermined` 的事件在历史页显示「目标待确定」；用户在设置页确认目标后，**对这批事件做一次性绑定**（写入 ledgerId + targetState=resolved），此后不再随浏览账本变化。
5. **失效判定**：账本行不存在 / 共享权限被撤（账本行被 purge）/ 目标 scope 与当前账号不符 → `targetState=invalid`，停止自动写入并提示修复；**不静默切到第一个账本**。

### 3.4 首次升级绑定（一次性迁移）

无 `auto_book_settings_v1` 时：

1. 按旧口径（Provider → `current_ledger_id` → 第一个账本）求得**当时的有效账本**，写入 target，`migratedFrom: "legacy_current_ledger"`，`confirmedAt=null`（表示**未经用户确认**）。
2. 配置页顶部展示「当前自动入账到：<账本名>」并要求确认；未确认前**保持旧兼容路径**（继续按旧口径入账），但状态卡显示「目标未确认」。
3. 迁移**只执行一次**，不随浏览账本变化重跑。

## 4. B3 约定：原生队列迁移与回退策略

### 4.1 存储

- 新增 `NativeAutoBookQueue.kt`：应用私有目录 SQLite（`android.database.sqlite.SQLiteDatabase`，系统自带，**不引第三方依赖、不打开 Drift 库**）。
- 库文件：`databases/auto_book_queue.db`；`PRAGMA user_version` 作队列库版本（首版 `1`）。
- 单表 `queue(event_key TEXT PRIMARY KEY, source TEXT, fingerprint TEXT, captured_at INTEGER, occurred_at INTEGER, target_ref TEXT, target_version INTEGER, target_state TEXT, payload_json TEXT, material_bytes INTEGER, expires_at INTEGER, acked_at INTEGER, enqueued_at INTEGER, migrated_from TEXT)`；索引 `(source, captured_at)`、`(expires_at)`。
- 事件键口径与现有一致：短信/屏幕文本 `sha256(pkg|timestamp|fingerprint)` 前 16 hex，通知沿用 fingerprint（补 eventKey 需在 B3 落地并保持与 Dart `notifyFingerprint` 同口径），截图以 `path` 派生 `sha256(path)` 前 16 hex。
- **不同来源的同金额同商家不共享事件键**；指纹仍按各路原算法，不重新定义。

### 4.2 容量与有效期（R02 首版参数，待真机验证后锁定）

| 参数 | 值 | 行为 |
|---|---|---|
| 每来源条数上限 | 500 | 达到 90%（450）触发「接近容量」提示并请求 Dart 有界处理；达到上限**拒绝新入队**，写入最小损失摘要（来源、丢弃条数、时间窗），不静默删最旧 |
| 总材料字节 | 20 MiB | 超限按「已过期 → 最旧未完成」顺序驱逐，驱逐记入损失摘要 |
| 未完成材料有效期 | 72 小时 | 到期置 `expired`，保留**无原文的过期摘要**（来源/事件键/时间）供历史页展示 |
| 截图材料 | 仅存可访问路径/URI | 不复制原图；路径失效 → 封套标 `materialMissing=true`，说明不可重放 |

以上为**工程起点**，不是产品承诺；不在任何文案中宣称「零丢失」。

### 4.3 交接与 ACK

- 入队（Kotlin）与桥接通知（broadcast/invokeMethod）**解耦**：入队先落库，通知失败不影响；Dart 靠启动/前台的 **peek-drain** 补齐（冷启动首秒桥接静默失败是既有竞态）。
- 分批 peek（默认 10 条/批，可配），Dart 处理到**可 ACK 终态**才移除；`failed`(可重试)/`noAiConfigured` 不 ACK。
- **提前交接（把元数据/材料写入 Drift 后即 ACK）默认关闭**：只有「跨存储交接、崩溃重放、重复 ACK」三类测试通过后才允许开启，且开启时交接点必须已确认**事件元数据 + 完整可重放材料**都持久化，不接受「仅 event store 元数据行」。
- 交接不写交易成功指纹、不跳过语义闸门。
- 跨库无原子事务：采用「先写目标 → 确认可重放 → 再 ACK」+ 事件键幂等，覆盖崩溃窗口。

### 4.4 迁移（旧 SharedPreferences 队列 → SQLite）

顺序：**旧队列快照 → 新库按事件键去重写入 → 校验（条数 + 抽样字段）→ 写迁移标记 `migrated_from='prefs:<key>'` → 切读新库**。

- 迁移可重复执行（幂等，按事件键去重）；**失败继续读旧队列，不清空旧值**。
- 迁移期间捕获继续可靠写入（写入方在切换前同时接受新旧两路，或迁移在持有同一把锁的临界区完成）。
- 切换前保留旧格式备份 key（`pending_queue_backup_<n>`，带时间戳，保留一份）。
- 回退：安全回退版必须**能读取新队列**（向下兼容读）或执行「停止捕获后的受控导出」；**禁止**直接降级到不读新队列的旧 APK。降级演练属发布前检查项，本计划不执行。

### 4.5 账号隔离

封套带 `scope`；处理期间暂停、注销、切账号时，只处理 scope 匹配的事件，其余隔离不投递，不把上一账号材料送给下一账号（对应 T17）。

### B4 实施说明（偏离与取舍）

1. **「10 秒撤销」与「已忽略恢复」是两条路径**：撤销是内存态 SnackBar（只回滚刚发生的那一条）；超过 10 秒走「已忽略」标签页，按事件子项恢复。两条都只**重建候选**，不创建交易、不撤销原交易。
2. **期望状态检查在 store 层**：`reopenItem` 只允许 `ignored → pending`，`changed==0` 即返回 false；`PendingDecisionCoordinator` 负责把同键操作串成一条链，防止快速重复点击执行两次 —— 不是只靠按钮禁用。
3. **规则作用域**：分类学习规则补 `ledgerId`/`disabled`（沿用 `category_learning_rules_v1` 键，旧条目解析为 legacy）；旧规则未绑定前保持旧口径全局生效，规则页顶部提示逐条绑定；`match` 过滤停用项与作用账本。
4. **学习规则落库时机改为入账成功之后**，并弹「仅本次 / 记住」让用户确认关键词（默认取商户，缺失才回落备注，可改写）——修正了计划点名的「规则先落库、入账失败也已记住」问题。
5. **未覆盖**：批量忽略的 10 秒撤销（计划只要求「普通候选忽略」有撤销，批量保留确认 ✓）；行内编辑只支持账户/分类两字段，金额与时间仍走完整编辑弹窗。

### B3 实施说明（偏离与取舍）

1. **读写切换**：四路的 enqueue/peek/ack 全部改走 SQLite；旧 SharedPreferences 保留三样东西：①「已处理」指纹/路径备忘录（ACK 前先取回原始项再写，避免删了就补不上）；②迁移标记；③迁移前的原格式备份 `pending_queue_backup_v1`。旧队列值**不先清空**（计划 §4 B3 任务 8）。
2. **迁移时机**：在首次 enqueue/peek/ack/stats 时同步完成（对象锁内），迁移期间入队与迁移互斥，满足「迁移期间捕获继续可靠写入」；迁移按 `(source, event_key)` 主键冲突去重，可重复执行，坏数据跳过不阻塞。
3. **桥接语义**：peek 返回本来源全部未 ACK 项（上限 500），Dart 侧改为**每批 10 条、批间串行**的有界处理；入队与桥接广播仍解耦（广播失败只影响及时性，靠 peek-drain 补齐）。
4. **目标快照必须写进 payload**：Dart 从 peek 的 payload 里识别冻结目标，因此 `NativeAutoBookQueue.enqueue` 同时把 targetRef/state/version 写列与写 payload（仪器测试抓到过只写列的缺陷）。
5. **提前交接（跨存储 ACK）保持关闭**：本轮全部沿用「到达可 ACK 终态才删除」，符合计划「先保留当前终态 ACK」。
6. **未覆盖**：并发 drain / 写交易后 ACK 前崩溃 / 冷启动首秒捕获的故障注入（计划 T08）需要更完整的测试脚手架与真实进程杀伤，本轮未做，记 NOT_RUN；vivo 真机 T18 BLOCKED。

### B2 实施说明（偏离与取舍）

1. **写入范围偏离**：`lib/services/ai/ai_bookkeeper.dart` 不在计划的 B2 写入范围，但「规则冲突/无法验证 → 待确认」的裁决点只存在于该文件（候选创建处）。实际改动限于：`createFromBill` 透传 `source`、新增 `on AccountRuleConflictException` 分支（约 35 行），未触碰该文件的既有未提交改动。已按计划「具体差异以每批复核为准」记录于此。
2. **作用域细化**：B0 §3.2 的 scope 匹配细化为「只有 `user:` 作用域做账号隔离；`local` 目标对任何账号有效」。理由：设备本地账本本身不随账号增删，把 `local` 目标判为失效会让「先离线开通、后登录」的正常流程直接停摆；`user:` 目标仍严格要求一致（切账号即失效）。
3. **旧版渠道规则**：B2 之前的规则没有作用账本 → 一律判为 legacy，**不参与**新优先级路径，仍走「AI 未给账户名时才生效」的旧兼容路径，并在映射页顶部提示逐条确认作用账本；确认后才进入新口径。
4. **规则失效的去向**：命中但无法验证（账户已删/隐藏/币种不符）抛 `AccountRuleConflictException`，由 ai_bookkeeper 落 `accountRuleConflict` 待确认候选；手动路径不带 sourceChannel，不会触发。
5. **原生目标缓存**：Dart 先写自己的 prefs，成功后再推 `com.smartbook.zhi/auto_book_target`；推失败只降级为「捕获时不冻结」，Dart 仍按当前配置解析，绝不回退浏览账本。
6. **未覆盖**：真机验证（切账本/进程重启/权限撤销/共享撤销）与原生编译均 BLOCKED；候选确认页在目标失效后的写入行为归 B4 复核。

### B1 实施说明（偏离与取舍）

1. `automation_settings_store.dart` 计划归属 B2，实际在 B1 提前建立：开通进度与目标引用共用同一版本化配置键，避免两份存储（计划 §5「不重复建设」）。
2. 开通页（setup page）保留自己的分步现场检查（授权后立即复查），但状态**快照**与首页、配置页同源于 `automationHealthProvider`；AI 维度通过 `automationAiStateProvider` 事件流实时覆盖，不重查原生桥。
3. 原生状态查询只读，失败一律回 `null` → 维度显示「待验证」；已开启来源查到「桥接未注册」时会延迟 1s **再确认一次**（冷启动注册竞态），不做周期轮询。
4. 模拟测试默认 `previewOnly=true`（影子模式，单次生效，不改用户设置）；写入模式先定位/名为「自动记账测试」的独立账本，找不到则创建，创建失败回落预览，绝不写入正式账本。
